# Root-only staged registration and new-consumer check

These are concrete orchestration instructions, not executed author evidence.
Root owns every command below and records the actual argv, outputs and guards.
This check validates staged registration plus the 15 new consumers against
accepted C02 Release dependencies. It is neither a clean build nor full native
acceptance; the five later native matrix legs remain required.

## Isolated source and predecessor guards

Use fresh paths below `/tmp/crown-c05-native-registration-stage-<attempt>/` for
`source/`, `build/` and `evidence/`; refuse an existing attempt. Do not configure
or write the real native build directories. Before copying, pin the final
implementation/publication manifests, accepted preparation aggregate and
`build/verification/c05-c02-predecessor-build-evidence.json`. Pin every native
source copied and every accepted Release archive, parser input, executable,
compiler and generated predecessor record used. Do not evaluate current or
historical source-seal entries as part of this stage.

Copy the actual current native source roots needed by CMake and the consumers:
`CMakeLists.txt`, `CMakePresets.json`, `dependencies.lock.json`, `README.md`,
`apps/`, `cmake/`, `include/`, `src/`, `schemas/`, `tests/`, `tools/` and
`third_party/`. Copy native top-level `docs/*.md` for the mapped guide
destinations. Do not copy `.git`, native build trees, temporary artifacts or
excluded proposal source trees as build inputs. The existing Boolean candidate
fixtures under `tests/` must be present. This scoped source copy is intentional
stage material, not a claimed independent clean-source snapshot.

Apply exactly the reviewed 34 rows of `source-map.tsv` inside `source/` only.
Require the three overwritten staged paths to match the real pre-edit bytes
before replacement, and the 31 new paths to be absent. Pin all resulting source
files and compare every mapped path with `source-files.sha256`. The staged
compiler must see the mapped native include/source paths, never an overlay path.

## Real CMake generation and inventory

Configure the isolated source with the same accepted Release C/C++ compiler
files and flags. The concrete configuration shape is:

```sh
cmake -S "$c05_stage_source" -B "$c05_stage_build" -G "Unix Makefiles" \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DCROWN_SANITIZERS=OFF -DCROWN_WARNINGS_AS_ERRORS=ON \
  -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \
  -DCMAKE_C_COMPILER=/usr/bin/cc -DCMAKE_CXX_COMPILER=/usr/bin/c++
```

Root must verify those compiler paths/identities against the captured accepted
Release cache before invoking this command, adjusting only to that actual
record if necessary. Record configure output and generated CMake/compiler/
parser-configuration files. Configuration runs CMake's normal compiler and GNU
Make checks; it does not authorize an old project C++ rebuild.

Require exactly 238 project target/source entries in the generated compile
database. Match the 24 new entries one-to-one against `target-inventory.tsv`,
using target/object identity as well as source path: the bridge source and
example source each have distinct production/testing entries. Compare the
remaining 214 generated entries with accepted C02 after only source/build-root
normalization; flags, macros and dependency roles must match. Verify the native
14-unit runtime and six-unit report lists are unchanged.

## Compile only the 24 new generated entries

Replay each of the 24 actual CMake compile-database argv in its recorded
directory, creating only its isolated object-output directories. Preserve
C++23, Release optimization, the six strict warnings and all generated include,
macro and assertion options. Add only full `-MD` dependency capture and an
explicit isolated `-MF` path if the generated argv does not already supply one.
Record the untouched generated argv and the exact executed argv with that
capture-only delta. No old project C++ unit and no excluded direct-build object
may be substituted. Retain per-command stdout/stderr, exit status, object and
dependency hashes; stop on a failed compile.

The partition is five pure library units, two matched bridge units, 15 consumer
units and two example objects. Only the testing bridge, census consumer and
testing example receive `CROWN_RUNTIME_TESTING`; pure/production entries do not.
The pure library and two pure consumers have no runtime/report archive. All
other consumers select exactly the expected production or testing bridge.

Replay the generated `CMakeFiles/<target>.dir/link.txt` archive recipes for
only `crown_selection`, `crown_selection_runtime` and
`crown_selection_runtime_testing`, in the isolated build directory. These three
outputs must be new regular files, never borrowed symlinks. Then replay the
15 new executable link scripts, for example through root's recorded
`cmake -E cmake_link_script ... --verbose=1` invocation. Use the exact generated
archive order and link flags; do not reconstruct a convenient handwritten link
line. The two example targets produce objects only and require no link.
Hash all borrowed archives before and after; no selection link may include a
report archive or both runtime ABIs.

## Actual registration and one execution of each new case

Use CTest's generated show-only JSON to retain all 158 names, order, argv and
properties. Compare the first 143 with the accepted C02 record after the same
source/build-root normalization, including every timeout, environment and label.
The existing `ranking_normalized_exceptions` timeout stays 3600 seconds.
Require the final 15 entries to match `new-ctest-commands.tsv` exactly; the
independent fixture arguments must resolve to the isolated source directory.
Confirm that the exact `C05` label selects precisely those 15 names and no old
test. Then root runs them once, serially:

```sh
LC_ALL=C ctest --test-dir "$c05_stage_build" -L '^C05$' \
  --output-on-failure --parallel 1
```

Preserve the complete output, CTest XML/logs, individual test statuses/durations
and the generated inventory. This is an ordinary Release stage; it does not
replace the already accepted excluded sanitizer runs or the later native
sanitizer matrix. Failure is retained as failure; corrections require a new
reviewed source/attempt rather than silently rerunning a weaker subset.

Finally recheck all copied/mapped source, manifest, receipt, compiler and
borrowed archive/executable guards. Retain the exact 24-command/three-archive/
15-link partition and all generated dependency/flag evidence. The root receipt
must label its outcome `staged registration and new-consumer evidence`, with
native integration and full 158-test/five-configuration acceptance still pending.
