## Completed execution generations

The final input manifest binds the accepted design/root review, final
implementation package, independent selected-source packages, independent
source review and terminal root ordinary/sanitizer receipts. It also
identifies each receipt's exact compiler-command, dependency, object, archive,
consumer and stdout/stderr provenance needed to review the claimed closure.
The root's preserved 17 + 1 + 1 producer strict translation-unit lineage is
explicit; it is not represented as 19 fresh strict5 compiles. The sanitizer
closure is fresh and must match the final source/API bytes and native runtime
variant. Native C++ archives and parser configuration are read-only inputs.

Historical strict1/strict2/strict3 and original independent failures stay

source guards. Current selected source and artifact identities receive their

A successful compile/link receipt is build evidence only. Runtime acceptance

the exact output/exit status. A preserved diagnostic failure is not counted as
a passing native test. Separate producer sweeps and independent focused
positions retain separate populations; no summed count implies a stronger
exhaustiveness claim.

## Manifest closure rules

All package/input/source paths use the repository-root convention already
used by the accepted C02 publication. Manifests bind exact bytes rather than
mtime or file size. The final package manifest includes every owned publication
file except itself, with no self-reference. The external input manifest does
not claim an acceptance record that requires this same package hash to exist
first. Final root review and native acceptance may bind this package afterward.

Mutable progress output, running-job files, unrelated S04 drafts and later
native results are excluded from the freeze. Root-produced terminal receipts
are included only after their producing guards close. No unexecuted result,
temporary compile shortcut or future source path becomes an accepted input.
`FROZEN.md` records actual entry/file counts after assembly; the expected native
compile/test counts above do not substitute for generated inventories.
