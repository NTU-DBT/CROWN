# Independent review of the CROWN C++ port (2026-11-20)

Scope: the C++23 "CROWN Next" implementation on `review/native-v73`
(~67k lines in `src/`, `include/`, `apps/`), checked for bugs, efficiency and
fidelity to *Change Propagation Without Joins* (PVLDB 16(5), corrected arXiv v2).
Fixes are on branch `review/native-v73-fixes`.

## Method

- **Static review.** 20 reviewers, one per subsystem: support, delta, physical,
  session, planner (4 units), weighted/aggregates, storage (2), resource/IR,
  extensions, windows/statistics, SQL frontend/runtime, recovery (2), I/O and CLI.
- **Dynamic testing.** 5 testers:
  - CQ differential fuzzing against SQLite;
  - SQL differential fuzzing against SQLite;
  - complexity/performance measurement;
  - a paper-to-code audit;
  - crash/recovery testing.
- **Adversarial verification.** Every finding got one or two independent
  verifiers (reproduce and refute lenses). Results: 100 findings; 82 confirmed,
  10 refuted, 1 uncertain, 7 duplicates of other verified findings.
- **Builds and tests.** Linux (Ubuntu 24.04, GCC 13.3, the documented
  toolchain), Release and ASan/UBSan, plus native macOS (Apple Clang 21).

## Correctness: no wrong answers found

Differential tests against SQLite and brute-force oracles found **no
correctness, rollback or memory-safety defect** in query maintenance. The
oracle compared exact signed deltas, accumulated state and snapshots after
every update. Coverage:

| Tester | Scope | Mismatches |
|---|---|---|
| CQ fuzzer | ~11,600 cases: 2–7 atoms, projections, Boolean heads, self-joins, constants, repeated variables, 60% random *non-minimal* free-connex trees (nested generalized nodes, height ≤ 7), all live-maintenance/completion policies, checkpoint/restore, rollback and refused updates | 0 |
| SQL fuzzer | ~9,000 bag/DISTINCT/COUNT/SUM/AVG/NULL cases, two ASan+UBSan runs, 1,800 durable-session cases, 720 `crown aggregate` CLI cases | 0 |
| Support / physical / delta reviewers | ~18k epoch checks, 9k self-join steps, hundreds of random-query delta fuzz runs (also under ASan) | 0 |

The paper audit found the semantics faithful to Def. 3.1/3.2 (cover, connect,
guard, above, connex; native-only height), the GYO free-connex test, the
q-hierarchical test, Alg. 1–6, live views (Lemma 5.5) and witness tuples
(Def. 5.6 / Lemma 5.7).

**Test gap.** `tests/property/reference_fuzz_test.py` (via
`tools/reference_fuzz.py`) drives the CLI `oracle` command, which runs the
*reference* evaluator, not the CROWN runtime. The repository's own property
test therefore never exercises the algorithm.

All fixes keep the existing semantics. Final status on the fixes branch:

- **Linux Release:** all 396 tests pass.
- **Targeted ASan+UBSan (Debug):** 38 tests covering the changed code. 24

## Confirmed, not fixed (recommended follow-ups)

### Deviations from the paper's cost guarantees
- **Aggregation (§7.3)** is not implemented as ring annotations.
  - SQL `SUM/AVG/COUNT(col)` arguments become head variables
    (`src/frontend/sql_aggregate.cpp:277`, `src/runtime/sql_aggregate.cpp:175`).
    Some free-connex GROUP BY queries are rejected, and a one-group update can
    cost Θ(N log N).
  - The weighted runtime includes connex children in w_s and propagates
    positive→positive changes to the root (`src/runtime/weighted.cpp:539`).
  - It does not coalesce same-key child messages, giving Θ(F·G) instead of
    Θ(F+G) (`weighted.cpp:612`).
  - Delta capture walks from the root, not from the changed key (`weighted.cpp:261`).
- **Ordered trees instead of hash indexes** throughout: support metadata,
  derivation counts, the default reference backend, live views and
  weighted/star maps. Every S/R/P probe is O(log N) full-row comparisons rather
  than O(1).
- **Delta enumeration is fully materialized** into a spool before publication
  (`src/runtime/delta.cpp:821`). This is the atomic-epoch design, not Alg. 6's
  streamed constant delay.
- **No GHD path (§7.1).** General CQs, set/bag difference (§7.2) and comparison
  predicates are recomputed from a full source copy on every update
  (`src/runtime/cq_recompute.hpp`, `fallback.cpp`, `difference.cpp`,
  `comparisons.cpp`). The original Scala code does have a triangle-bag GHD.

### Efficiency
- **Memory: ~4.7–6 KB and 27–33 accounted allocations per stored 2-column
  tuple.** An 88-byte header per allocation, 56-byte cells, and up to three
  copies per tuple. 74 allocations per insert. The default 256 MiB query budget
  holds only ~140k tuples, so `--memory-limit-bytes` is needed for
  paper-scale data.
- Enforced FK/UNIQUE constraints copy and re-validate the whole database on
  every update (`src/runtime/physical.cpp:323`).
- Physical-FIFO window watermark preflight copies and sorts all live rows on
  every tick (`src/runtime/window.cpp:173`).
- Smaller hot-path costs:
  - workload counters clear the whole slab per update; NDV capture uses a
    linear search;
  - `query_identity` permutes self-join atoms factorially (8-atom self-join paths
    fail);
  - the JSONL reader reads byte by byte with ~24 allocations per record;
  - ~5 KB is copied per delivered row;
  - SQL frames are re-hashed several times.

### Robustness edge cases
- A crash between publishing the generation root and creating the sink leaves a
  root that neither `run` nor `restore` accepts (`apps/crown/workflow.cpp:363`).
  An orphaned first-generation candidate blocks the root path
  (`src/recovery/generation.cpp:278`).
- `enable_generation` latches `recovery_required` on failures before any root
  exists (`src/runtime/session.cpp:1020`).
- Sinks are never rotated, and reopen rescans and rehashes every epoch.
  Per-file caps (1M epochs / 1 GiB) remain lifetime caps on output.
- `restore` treats an input truncated below the consumed prefix as end of
  input. The JSONL reader commits an unterminated final line.
- Smaller CLI issues:
  - `results --epoch` reports `checkpoint_invalid` for undelivered epochs;
  - maintenance mode writes empty sink epochs;
  - a spool-limit refusal cannot be overridden on restore.
- Pinned libpg_query 18.1.0 calls `memcpy(NULL, …, 0)` (UB) when deparsing
  empty strings.

The per-finding records (description, scenario, verification and repro path)
are in the review scratch area: `build/review-scratch/verification_state.json`
and the workflow journals.

## Environment notes

The full test suite needs Python packages `jsonschema`, `referencing`,
`duckdb` and `matplotlib`, plus GNU `time`. Without them, 41 integration tests
fail for environmental reasons.
