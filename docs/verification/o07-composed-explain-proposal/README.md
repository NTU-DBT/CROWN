# Composed O07 EXPLAIN proposal — not native integration

O07 remains **NS**. This package is an excluded, unapplied implementation proposal. All generated programs were compiled/linked only; none were executed here. No native source, CMake target, prior proposal, accepted test, ledger, or historical seal was changed. Compiler checks establish interface/link consistency, not acceptance, correctness, sanitizer cleanliness, performance, or full O07 verification.

## Final owning report API

`crown::observability::PlanExplanation::create(PhysicalPlan, HeightEvidence, CandidateSnapshot, ExplainLimits)` is compile-only. `capture(const DeltaRuntime&, ...)` and `capture(const QuerySession&, ...)` capture real owners. Session capture obtains the session's actual immutable `PhysicalPlan`; there is no caller-supplied plan/owner/hash association. Optional height/candidate handles still require exact original native catalog/query equality, including all typed values, constraints, statistics, aliases, occurrence order and output order. Hashes are navigation identities only.

`ModeDescriptor` owns current/retained owner metadata. Its nullable `state()` and `presence()` distinguish compile-only, live, stopped-retained and released. Begin-bound attempt/cursor configurations remain independent immutable values and are never relabeled by a later mode or benchmark-label change. Copied report handles own their plan/proof, metadata, copied numeric gauges and sampled trace records through later updates, mode switches, stop/drop, facade destruction and report moves. Moved-from report access is rejected consistently with the prototype.

The only new runtime seam is `QuerySession::report_metadata()` plus `report_gauges()`. A privately constructed `SessionReportMetadata` owns immutable compiled plan metadata, exact DeltaOptions, scalar/static-string runtime profile, owner, sequence and optional state. The session retains this metadata at construction and existing summary publication/release points with nonallocating noexcept copies. Drop releases runtime tables, rows, windows, queue, cursor and trace storage as before; retained plan/schema/options metadata is explicit and is not retained runtime data. `report_gauges()` returns null while any private physical/window work exists or after drop. It does not drain, cancel, prepare or advance. Stopped sessions retain a real readable runtime; dropped sessions report null runtime state and unavailable gauges.

Capture is a creator-thread, exclusive owner read. No callbacks run between its constituent read seams. It may allocate its own report, a bounded-by-configured-retention numeric trace copy, and an explicit committed gauge snapshot. It performs no search, certificate replay, class recognition, cursor advancement, JSON encoding or result mutation. Failure releases temporary report allocations and leaves the owner unchanged. Observation-off capture remains allowed and can obtain committed gauges through the explicit allocating diagnostic read; optional counters/timings remain disabled. This explicit capture is not a hot hook or a claim of zero diagnostic allocation.

## Integrated transport and authority

`crown::io::write_explain_json/text/dot/tree_json` overloads accept either the owning `PlanExplanation` or the independently owned `QueryExplanation`. The final physical/runtime/session JSON artifact is version 2 and **contains** actual run context, session status, begin-bound labels/output disposition, latest cursor, gauges, registry values and sampled causal records. The run-context/cursor/gauge component objects are integrated nested objects, not separately linked files. There are no compatibility fallbacks that silently omit new fields. The frozen prototype CLI/schema are superseded for final composition.

The query form contains the complete closed query/search report: actual ExactSearch or CertificateReplay continuation progress, interrupted/budgeted states with or without an incumbent, genuine checked upper, verified optimum, or verified structural infeasibility. It never requires a fake physical plan. Native producer status, stops, counters and limits remain actual owner observations. No capture/export step advances a producer. Tree/DOT export requires a genuine retained checked witness; unavailable witnesses fail export without fabricating a tree. Known-class analysis remains explicitly `not_collected` when the producer has not supplied it; capture does not silently run a recognizer. Physical class/guarantee metadata comes from actual P08.

**Height domains:** a P08 `constant_false` operator has executable height 0. For a nonempty contradiction-marked CQ, this does not establish an original P06 structural-tree upper bound or optimum. With no genuine structural evidence, final `height_evidence.status=checked_constant_operator`, scope is explicitly operator-only, and original upper/minimum/witness/lower claims are null. `structure.height_domain=executable_operator`; tree export scope also identifies the shortcut. Other selected P08 validated trees supply a checked upper only. Genuine compatible original proof handles may establish original structural claims, including an empty-body structural height-0 proof. A cyclic nonempty contradiction-marked query can be structurally infeasible while its executable operator is constant-false: these are compatible facts from distinct domains. Structural infeasibility is not a statement that no executable backend exists in all semantics.

Every metric has a registry unit/scope/accounting relation and availability. An unavailable raw internal payload (including the physical-cap aborted raw value 4) serializes as null, never a numeric total. Actual zero remains numeric zero. Work inclusion follows the runtime's sticky successful nested-charge bookkeeping; support work must not be added again to inclusive physical work. Aborted attempts report attempted work and unavailable incomplete totals. Current/last attempts retain their own resolved mode/options/generation and output lifecycle; caller-declared adapter/codec/sink/run labels have **unmeasured, no-authority** provenance. A label does not identify a `std::function` implementation, measure a sink, or promise durable delivery.

The latest cursor is one enabled cursor lifecycle publication, not a global total or delta output spool. Startup, successful next, exhausted next, failed call and cleanup phases exclude caller pause. Epoch-view cursor timings can be nested inside delta propagation/internal timing: these wall times are not additive. For a fake clock, compare the immediate attempt interval with delta clock reads plus the nested-cursor subset; compare any later committed cursor interval separately, and do not add that nested subset twice. Off/counters retain zero optional clock reads. The registry and component object expose limits, mandatory saved work, terminal status/reason, cursor configuration and source/snapshot side. The report does not create a new cursor.

Trace capture copies actual bounded retained numeric records, with kind/event/cause/node/occurrence/role/tuple IDs, no tuple pins or borrowed strings. Absent IDs encode null. Disposition, retained/dropped counts, saturation and truncation remain explicit. A sampled, truncated or aborted record list is not a complete committed history. A report captured before session drop owns its copy; a newly captured dropped-session report has released trace storage and zero retained records. Numeric IDs are scoped to their captured owner/attempt, not global persistent identities.

Committed gauges contain actual base tuple counts, node records/survivors/projected keys, and available E-factor cardinalities. Full join-result count, allocator/live/checkpoint bytes, checkpoint timing and recovery replay length remain unavailable where unimplemented. Pending/prepared/paused private work is a valid report state with `pending_private_state` gauges, not a capture error. These explicit reads do not change update cost counters. Component accounted bytes exclude allocator overhead, transient copies, metadata and caller retention; no S05 total-memory or performance claim is made.

UTF-8 and encoded-byte caps apply only at explicit text export. Native byte-valued bindings and labels are admitted/copied as native data, including arbitrary byte strings. Invalid UTF-8 fails text export without changing runtime/proof state. JSON is streamed into a bounded returned string; no JSON DOM participates in admission or unwind. Nested exporters receive the remaining encoded budget. An export either returns a complete artifact or throws. This is an encoded output cap, not a total allocator/CPU budget; nested strings and owned diagnostic copies are additional transient memory.

## CLI surface

The linked `crown-explain-composed-proposal` supports:

- `physical PLAN [--certificate CERT --proof-work N]` for an imported/revalidated physical plan.
- `runtime PLAN [runtime-options]` for an actual empty runtime construction.
- `session PLAN [--input FILE --input-format jsonl|binary] [runtime-options] [--events N] [--steps N] [--consume discard|transfer|retain] [--lifecycle preserve|stop|drop]` for an actual owned-stream session. Events default to zero; steps is an optional total preparation-step cap, allowing an honest pending/private report. Transfer is ownership transfer, not sink delivery or serialization; discard uses the real drain path.
- `query DOC` or `progress DOC [--height-policy strict|best-found] [--work N]` creates an actual search owner and optionally runs one explicit work quantum before capture. Default work is zero. `replay DOC --certificate CERT [--work N]` does the corresponding actual replay. Producer/replay construction limits remain native defaults and are reported. This CLI work is explicit; report capture remains read-only.
- All forms support `--format text|json|dot|tree-json` and `--max-bytes N`. Physical runtime/session options include `--mode maintenance|delta`, `--observe off|counters|timed|trace`, `--live on_output|incremental|eager`, `--completion automatic|ordered_replay|anchored|root_first`, `--view core|sql`, `--work-limit N`, `--spool-rows N`; optional `--run-label`, `--adapter-label`, `--codec-label`, `--sink-label` are declarations only.

Physical optional certificate replay is an explicit operation before capture and requires a genuine checked optimum within the proof quantum; it is not a JSON flag. CLI artifact inputs have a 16 MiB input cap. Unknown/inapplicable or duplicate options fail. Errors emit sanitized codes; usage/text encoding/resource failures return 2/3/4 respectively, other errors 1. No CLI command was executed by this author. The library captures direct/replay/rebuild construction, typed/window sessions and their actual exact input/run options; the isolated CLI stream entry point is intentionally jsonl/binary and does not replace O08's broader command workflow.

## Acyclic native integration and compiler closure

`source-map.json` resolves each proposed native path to the highest frozen layer or this overlay. `composed-incremental.patch` is applied only after Runtime → Mode → RunContext → Cursor plus the physical/query report proposals; `composed-native.patch` is the full consolidated source/header/schema patch against the pinned native tree. Neither patch was applied. Neither includes a CMake mutation or the obsolete prototype CLI.

Proposed native target ownership is acyclic:

1. Existing `crown_core`/planner search remain unchanged. QueryExplanation and its query IO can form `crown_query_explain` depending only on core (four frozen query units/headers; two compiled source units).
2. Existing plan/sql depend on core as before. The complete runtime target adds `src/runtime/observation.cpp` and uses all layered support/physical/delta/session/window/replay/IO support/inspection units; no runtime header includes report or report IO.
3. `crown_explain` contains `src/observability/explain.cpp`, `src/io/explain.cpp`, `src/io/run_context.cpp`, `src/io/cursor_observation.cpp`; it depends on runtime, plan, query-report/core and SQL as needed. Public final IO includes both owning report types.
4. `apps/crown-explain/main.cpp` depends on this final report target and native document/physical/certificate IO. Installing schemas and adding native independent tests belong to root integration.

All **nine** runtime translation units were rebuilt for O0 with `CROWN_RUNTIME_TESTING` and O3 production without it. All **seven** report/CLI source consumers were separately rebuilt and linked to the matching complete archive. Never mix older runtime objects/archives or old test objects with these options/observation layouts. The final session metadata API additionally requires rebuilding its consumers. `abi-source-audit.json` traces quoted includes for 49 non-runtime units, including core `src/io/batch.cpp`/`include/crown/io/batch.hpp` and replay/window closure; none consumes changed nested runtime option layouts. Existing pinned core/plan/sql/libpg_query archives are reused only under that audit. Compiler-generated `.d` dependency hashes, commands, object/archive/binary hashes and strict flags are recorded in the four evidence files.

Reproduce compiler-only checks with `build_runtime.py OUTPUT --testing --opt 0`, `build_runtime.py OUTPUT --opt 3`, then `build_report.py OUTPUT --runtime-evidence MATCHING/compile-evidence.json`. Output directories must be under `/tmp`. To regenerate source mirrors in this new package only, use `prepare_overlay.py`, `compose_io.py`, `extend_trace.py` in that order; the CLI is an authored source file. Regenerate schema and patch separately. The source generators never apply their patch.

## Independent acceptance contract and remaining gates

Root owns execution. In addition to prior accepted layer tests, final composition requires independently asserted human/JSON/schema/CLI cases for:

- compile-only and actual runtime/session captures in off/counters/timed/trace, empty/direct/replay/rebuild construction, exact input/queue/window/snapshot limits, absent versus declared context, mode/label changes and immutable earlier reports;
- current pending/paused/draining/prepared state, stopped runtime retention and dropped metadata, no advancement/output consumption from capture, gauge unavailability for private window metadata even when underlying delta is ready, no retained rows/leases after drop;
- copied causal traces before/after updates/drop, dropped count saturation/truncation/unsampled/aborted states, no tuple pins, exact numeric IDs and owner/attempt scope;
- current/last begin configuration versus current configuration, real retention/discard/transfer/serialization/sink disposition, failed callbacks/retries without falsely claiming delivery;
- latest cursor identity, source, active/terminal/failed/cancelled scope, active timing excluding pauses, exact zero versus unavailable, and immediate attempt clock reconciliation distinct from later committed cursor reads;
- support40/physical44 and unary21/25 hand traces, cap43 incomplete total, and a constraint-scan abort whose physical raw count exceeds support while inclusion is still unavailable; no clamping or double count;
- plain validated tree upper, genuine optimum/candidate/family evidence and exact-binding mismatch rejection, normalized SQL, raw non-UTF8 native bindings admitted but text export rejected, escape-expanded byte-cap boundaries;
- nonempty contradiction-marked cyclic body (operator0 but original structural upper/minimum null), empty-body genuine structural0 proof, and separate typed structural infeasibility without a physical plan;
- exact/replay status families, strict hidden upper versus exposed best-found incumbent, genuine depth/work budgets and resume, no witness tree export without checked witness, closed schemas rejecting unknown fields;
- allocation failure during report/trace/gauge/text capture leaving session state, mandatory work, optional clocks and proof owner progress unchanged. Session metadata retention hooks themselves must remain allocation-free.

Current source implements the mode/context/cursor/report wiring; those are no longer design-only missing fields. Remaining gates are independent execution of this exact composed package, native integration and complete required native matrices/sanitizers, O07 acceptance reconciliation, total S05 allocator accounting, O04 checkpoint/O05 recovery/O06 durable delivery, C01 statistics/C02 cost ranking, B03 benchmark validation and O08 release/workflow integration. Existing prior-layer passes do not certify this newly composed source. No global optimal-cost, durability, uniform resource or performance claim is made.
