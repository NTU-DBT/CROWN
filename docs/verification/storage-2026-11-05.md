## Acceptance audit

| Required artifact or behavior | Evidence |
| --- | --- |
| Typed identities | Central `ir/ids.hpp` defines catalog, occurrence, node, relation, layout, field, tuple, index and storage-owner IDs. Existing frontend occurrence and tree APIs retain their types/wire representations. Handles include storage owner and relation, and reject foreign ownership. |
| Immutable layouts and owned tuples | `storage/layout.hpp` and `src/storage/layout.cpp` validate scalar kinds, exact decimal domains, repeated-variable equalities and positive source/catalog versions. Layout copies share an immutable runtime token; independently equal descriptors do not. Tuples own strings/scalars and expose const views. Copy assignment preserves the previous tuple on allocation failure; self-move preserves its invariant. |
| Compiled numeric key programs | `Projection` checks domain inclusion, source slots and repeated-variable proofs once. Applying it checks the source token and copies fixed numeric slots without string field-name lookup. Composite, reordered, repeated, nullary and 70-column projections pass. Shared explicit target tokens make keys from different source layouts interoperable. |
| Exact typed equality and hashes | Value tags distinguish integer, string, bool, date and exact decimal values. Canonical decimal spellings compare/hash equally. Tuple equality also checks the layout token. The reference backend uses ordered comparisons and exact equality; a hash is never a membership proof. Existing scalar/catalog hash and exact-domain tests continue to pass. |
| Strict versioned codecs | `io/layout.hpp`, `src/io/layout.cpp`, `tuple-layout-v1.schema.json` and `key-projection-v1.schema.json` encode complete descriptors and programs. Native readers reject unsupported versions/semantics, duplicate/unknown fields and invalid IDs/types/domains. Projection replay compares complete descriptors and explicitly binds caller-supplied tokens. |
| Primary and secondary storage | `ReferenceTable` uses standard maps/sets, primary full-row equality, a tuple-ID lookup and secondary key-to-member buckets. Registering an index builds its existing-row memberships before publication. Empty buckets disappear; nullary keys work while one or more rows remain. |
| Independent randomized comparison | `tests/unit/storage_model_test.cpp`, delegated to Luna Max, runs 12 seeds × 100 operations against an independent map-of-sets model. Expected keys use raw positional extraction, not production `Projection::apply`. Six key shapes include reordered/repeated/nullary keys over exact scalar types. Every step compares primary rows, keys, buckets, handles, live/bucket traversal and rebuilt invariants. |
| Duplicate/absent operations and key deletion | Random operations cover insert, erase, erase-by-key, clear, add/drop index and no-ops. Targeted checks cover shared keys from distinct sources, foreign handles, missing keys, owner destruction, moves, monotonic tuple/index IDs and empty/live bucket behavior. Key deletion removes matching rows from the primary table and all indexes together. |
| Cursor and ownership contract | Live and bucket cursors visit current entries only, hold a weak owner and check revision before touching saved iterators. Real row/index mutations invalidate them; duplicate/absent no-ops do not. `snapshot()` returns owning tuple copies. Borrowed row pointers have explicit erase/clear/destruction lifetimes. |
| Failure atomicity | A separate allocation-fault binary sweeps each allocation before successful insertion (14 points), index creation (61), bulk nullary-key deletion (50) and tuple copy assignment (2). Failures leave rows, buckets, revision and existing cursors intact; tuple/index IDs remain available for retry. The successful bulk deletion leaves no empty buckets. All sweeps run in each build configuration, including sanitizers. |

The tuple self-move regression was first observed failing under the defaulted
move assignment. A guarded `noexcept` move assignment fixes the layout/value
mismatch; the final matrix includes that regression. The failing observation
is retained in `build/verification/storage-self-move-regression.log`.

## Boundaries and next work

This is the first standard-container storage backend. Operations are
single-threaded and provide per-table strong exception guarantees. Multi-node
epoch atomicity, record pinning, arena reuse/generations, optimized native
hash indexes, quotas and complete memory accounting remain S03–S05/R04.
There is no maintained join/result runtime or runtime snapshot/delta cursor.
The owning storage snapshot is an explicitly copied vector, and no runtime
complexity guarantee is inferred from these finite tests.

P08 can now lower independently validated trees to shared tuple/key layouts,
index requirements, event routes and an enumeration program. Its constructor
must bind/revalidate the actual query/catalog/tree, reject unverified plans
and keep validity/checked height separate from optimality evidence. S03 can
proceed from the verified reference backend. R01 follows P08/S02. A02's
license/provenance disposition, P04/P06 partial features and G2/V02 independent
mathematical review remain open. S01/S02 do not close release gates.
