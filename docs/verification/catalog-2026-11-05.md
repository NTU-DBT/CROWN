## Enforcement and independence

Enforced unique keys and foreign keys are checked on the initial database and
every complete candidate after-state, across all physical relations. A foreign
key requires an enforced unique target on the same column set; field order
may differ. The reference session commits only after validation and all result
allocations. Unit checks retry the same sequence after rejected parent
deletion, key conflict and missing-target insertion, proving the database,
sequence and owned output remain unchanged. Effective/no-op updates,
self-reference, multiple projected witnesses and empty keys are exercised.
No cascade or constraint-based query rewrite is implemented.

The new integration driver uses independent SQLite tables with
`PRAGMA foreign_keys=ON`, ordinary `INSERT` constraints, explicit full-row
duplicate prechecks and `SELECT DISTINCT`. It does not use `INSERT OR IGNORE`,
which would hide unique violations. Four valid v3 traces contain 13 raw
initial rows and 16 events: composite/reordered FK projection witnesses
(6 rows/9 events), self-reference (0/4), misleading untrusted declarations and
statistics/hints (4/0), and fixed decimal `(5,2)` values (3/3).
There are 21 invalid standalone catalogs, eight rejected CQ traces, one rich
standalone catalog (four tables including a nullable source), v1/v2 semantic
compatibility traces, canonicalization and three binding-format checks.
Normal and Python `-O` runs pass. Python fixed-spec expectations use Decimal
rescaling/integrality/range, independently of production digit counting.

A bounded static review by a separate Luna Max agent found no concrete
ownership, validation or serialization bypass in the scoped catalog paths.
That is code-review evidence, not external G2/V02 mathematical signoff.

## Version and schema checks

CQ format 3 carries the new metadata and preserves it on roundtrip. Formats
1/2 keep their old shapes and reject metadata loss. Standalone catalog format
1 is independent of CQ document format numbers. Catalog and source versions
remain exact positive uint64 values. Owners must advance catalog versions on
schema changes; reference sessions own their catalog copy. No online migration
or physical-plan invalidation mechanism is claimed.

Certificate bindings choose format 3 for nondefault metadata, otherwise 2 for
date/decimal catalogs and 1 for primitive catalogs. Changed source versions
invalidate exact bindings. Source data is excluded. Schemas and native checks
preserve typed values and reject silent version/field defaults.

All seven schemas pass Draft 2020-12 meta-validation with locally resolved
references. Actual rich catalog input/canonical output, all four v3 fixture
inputs/canonical outputs and their height certificates pass their schemas.
Their certificates also pass the standalone replay CLI. A separate varying
fixed-scale equality example joins `(4,2)` values `1.20,1.23` with `(5,3)`
values `1.200,1.234` and returns exactly `1.2`, without conversion/rounding.
Optional manual schema checks use installed jsonschema 4.10.3; it is not a
CTest dependency.
