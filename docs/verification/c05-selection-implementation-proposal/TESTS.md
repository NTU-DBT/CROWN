## Oracle and authority boundaries

The public fixtures construct original proof/candidate handles through finite
P06/P07 public work grants. They identify literal native-S/generalized-x/
generalized-y shapes without assuming enumeration position. They assert every
candidate's published scores, completeness and terms and initialize returned
plans against actual data. The separate independent author reconstructs the
full literal per-node/per-index term map; C05 does not duplicate or modify the
already accepted private exact-arithmetic backend.

The private binding consumer constructs editable diagnostic records to test
framing and field inclusion, including private copied C02 EvidenceData. Those
copies are used only by the byte-returning record/key helper. They are never
passed to `select`, `select_current`, a result factory or cache installation.
The private cache counter case seeds UINT64_MAX only to reach an otherwise
impractical counter-overflow boundary. The budget arithmetic fixture similarly
tests transport counters, not a claimed observed MAX-sized census. Neither
kind is public proof/evidence authority.

The existing testing saturation probe changes several real counters/generations
together. Its case verifies conservative actual-owner handling and the separate
source-only policy; it does not independently attribute the decision to one
flag. C02's existing classifier/actual-owner suites remain separate predecessor
evidence.

The exact/one-under public boundary cases exercise dimensions actually consumed
by their DirectCQ assessments and first DirectCQ lower. Real normalized fixtures
cover zero replay/normalization caps and the complete authored persistent-fault
paths; they do not establish positive exact/one-under replay and normalization
thresholds on a real normalized owner. Private aggregate-transport algebra is
not a substitute for that narrower runtime boundary check. This limit must remain
explicit in final coverage claims.

## Persistent-failure protocol

The two fault consumers replace scalar, array, sized, nothrow and over-aligned
global allocation/deallocation forms. A selected allocation index causes that
allocation and every later allocation within the attempt to fail. Setup,
expected images and verification occur outside the injected interval. Normal
and matching sanitizer binaries must execute the unchanged source.

Each sweep first measures the allocations of one complete attempt, then visits
every reached position below that measured count. The fixed guard of 200,000
positions prevents an accidental unbounded harness, not a claim of how many
positions will run. The printed counts and recovered-cleanup counts come from
execution only. An injected failure can produce a fully correct success if the
already patched native JSON destructor handles a cleanup allocation failure;
otherwise it must produce the documented allocation/native-resource failure
without any cache/owner mutation. No assertion is weakened to accept a partial
result or fallback.

Owner comparison includes owner ID, committed sequence and complete canonical
state. Workload comparison explicitly enumerates every Stamp, Metadata and
Memory field plus plan, options, modes, previous modes, current/previous cells,
descriptors, pending/history and interval bounds. Cached keys, physical bytes,
entry payloads, FIFO order and every statistic must remain identical on failure.
Old results retain all full score/term/physical descriptor images and Usage;
typed snapshot/proof/candidate validity and keys must remain intact. A clean
retry after every sweep must return the same complete bundle.

2. Execute short ordinary cases before the full persistent sweeps; retain their

   production/testing archives and the same active patched JSON header. Run
   AddressSanitizer, UndefinedBehaviorSanitizer and leak checks, including full

   ordinary C++ objects.
4. Execute independent public/byte/fault consumers against the same final API
   and implementation closure. Inspect all findings before implementation freeze.
5. Later publication, independent registration review, guarded native application
   and the full native matrix are separate required gates. C05 remains excluded
   until root explicitly performs them; this packet does not change card status.
