## Exact limits of the claim

Canonicalization implements the declared alias/order/local-expression profile,
not general SQL equivalence, atom elimination, containment or implication.
Equal-color labeling can be factorial and may stop on its operational budget;
no partial canonical hash is returned. Catalog/schema order remains fixed.
Output names use a separate contract digest; cache consumers must translate
canonical IDs and validate their plans against the actual query.

Normalized v1 is a source-bearing replay format, not a runtime checkpoint.
Future producer changes must preserve its replay behavior or introduce an
explicit version/upgrader, including changes to work counters. Replay does
not authenticate who authored a valid program. Certificates retain their
original exact query binding and independent mathematical replay; new hashes
cannot substitute for it.

F06 must now combine the existing normalized SQL boundary with GYO and
structured admission reasons. S01/S02, physical plan lowering, actual cache
installation and generic incremental runtime/cursors/recovery remain open.
A02 license disposition, P04/P06 partial features and G2/V02 review remain
as recorded in the full ledger. No release gate is silently reduced.
