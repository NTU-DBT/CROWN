2026-11-07. **Excluded test preparation only. C01 remains `not_started`.** The production strict and matching sanitizer consumers compile and link. No test binary has been executed by this author, so the seven groups below are proposed assertions, not observed passes.

This package consumes the frozen [combined implementation](../c01-statistics-combined-proposal/README.md), package-manifest SHA-256 `cb0ecb64935f80bf4915aa069de1bf01bcf1ea2f22a591f6f7408d405fcf4cfe`. It changes no implementation, native test, CMake, schema, serializer, project status or handoff file. The existing delta policy/replay/window fixtures being prepared by root are outside this package.

[scalar_statistics_test.cpp](scalar_statistics_test.cpp) is one standalone production-only consumer with seven groups:

| Group | Independent expectation and assertions |
| --- | --- |
| 1. Int64 ordering | A literal ascending list contains both signed endpoints, adjacent endpoints, negative one, zero and one. Two distinct source witnesses per key test projected multiplicity. Projection and existing-index captures must return the same literal NDV/histogram/heavy ordering. |
| 2. Boolean ordering | Literal `false`, then `true`; typed keys remain Boolean. The same projection/index, multiplicity, heavy tie and budget assertions apply. |
| 3. Date ordering | Literal chronological order includes 0001-01-01, 9999-12-31, pre-epoch/epoch, and leap-day values. No expected ordering is obtained by sorting the production Date values. |
| 4. Decimal ordering | Literal numeric rank covers negative and positive 38-digit coefficients, scale-38 smallest magnitudes, 38-digit fractional coefficients, sign changes, canonical zero, differently scaled positive neighbors and large exponent differences. Distinct physical witnesses use `-000.000` and `+001.2000` aliases while expected keys remain canonical zero and 1.2. |
| 5. Binary string ordering | Literal unsigned-byte order includes empty strings, embedded/leading NULs, prefix relationships, two 1024-byte strings with a long common prefix, DEL, 0x80 and 0xFF. No UTF-8 interpretation is used. |
| 6. Typed aliases and generalized state | A full mixed-type key feeds two aliases of one source table. One alias accepts every row; the other requires tag zero. Ignored tags collapse multiple source rows into one native tuple. A source-set/map oracle predicts both derivation maps, generalized candidate union/intersection, all actual S/P/E populations, existing visible-index degrees and every workload cell. Reordered/repeated/empty source projections, a repeated query output, no-ops, filtered routes, positive-to-positive derivation changes and erasures are exercised. |
| 7. Enforced constraints and rejected work | An existing supported singleton-query shape projects child rows onto `(parent, amount)` and visible parent keys. Child/parent unique constraints and a child-to-parent FK are enforced; the parent table is deliberately unrouted by the query. The test proposes orphan insertion, duplicate-key insertion, referenced-parent deletion, fixed DECIMAL(4,2) overflow, an explicit drained rollback, valid same-sequence recovery, canonical duplicate no-op, and final deletions. All failures must preserve the actual owner, committed epoch, canonical state and committed workload cells. |

The five scalar groups use 42 literal distinct values in total. The expected heavy ordering sorts integer positions in those literal lists, never `Value`, Decimal or string keys. All initial multiplicities tie at two, forcing the collector's key tie-breaker to be checked over the full list. Making the first and last keys heavy then checks top-three ordering; top-zero remains a known empty vector. Repeated single-key fields and the empty projection are checked separately. Exact/one-under charged-work limits and a zero-row limit require unknown NDV/histogram/top-K while cardinality remains known. Retained owning results survive table clear.

The owner oracles use ordinary small `std::set<Row>`/`std::map<Row,uint64_t>` populations and the existing native scalar representation/equality. They do not call plan adaptation, production statistics grouping, Cell::observe/merge, O07 traces or runtime snapshots to calculate expected state/cells. After every committed input they independently regroup the literal source set and check the event oracle's native maps against it. The separate literal scalar-rank groups cover the ordering assumption used by those maps. Descriptor definitions locate semantic cells; all returned numeric cells are compared against independent arithmetic, including histogram bins computed by repeated division.

The typed trace proposes 22 committed inputs, including canonical duplicate and absent-delete no-ops. The constrained trace proposes 14 committed inputs and seven aborted attempts: five real PK/FK violations, one fixed-decimal row-admission failure under the outer Delta root, and one explicit rollback after detail work. Every admitted attempt is selected (`period=1`), so attempt/selected/aborted counters must remain distinct from committed/complete counts. A rejected source update does not become a committed physical input. The test also checks input-share denominators, exact event availability, unavailable arrival Hz, no degradation flags, immutable historical typed facts after reset, and a shared state-row cap that preserves an earlier exact component while exhausting later components.

Limits are explicit and finite: state work 2,000,000, rows/keys 8,192, accounted component bytes 8 MiB, projection width 8 and heavy keys 64; workload admission at most 512 cells and 256 detail actions per selected input. These byte fields retain the frozen implementation's component-payload/capacity semantics and exclusions. No total allocator/peak-memory, native overhead, timed C01, serialization, future arrival model or cost-ranking claim is made.
