# Closed SQL cold reconstruction: receiving verification

The [public factories](../sql_source_images.md#closed-cold-reconstruction) rebuild
genuine physical/source/native/group state into a fresh receiving owner. They
replay the actual source/tree/options binding, validate the whole physical image,
restore coherent C, close cold grants and install the original normal context.
They add no persistent update field, joined-row ledger, public live sequence
setter, production catch or second undo system. Durable W06 remains open.

## Executed maintained and installed checks

All **19 selected tests pass** per strict C++23 warnings-as-errors profile:
Debug **119.15s**, full ASan/UBSan/leaks **312.03s**. The cohort covers native
program/storage work, weighted propagation/capture/enumeration and independent
oracles, ordinary aggregate/source/runtime/binding controls, source images, the
new cold factory and continuing original-SQL oracle. Both backends run in the new
controls. All required native drivers are rebuilt/relinked with the changed
libraries. Complete `BUILD_TESTING=OFF` production Release also builds successfully.

Registration is **333**, preserving all 331 predecessor commands and execution
properties except line backtraces. Only `sql_aggregate_rebuild` and
`sql_aggregate_rebuild_oracle` are added. The OFF build keeps the production
library and excludes the new tests. Execution of all 333 and a Clang gate are not
claimed by this packet.

The relocated **220-file SDK** passes a strict public consumer using only its
installed target/headers. It rebuilds a real filtered join with hidden separator,
unused/NULL source rows and original domains on both backends, then commits the
next physical epoch and checks the exact COUNT transition 8→4. Releasing the
image returns the original account to its controller while the restored owner
remains live; closing that owner returns the receiving account to its controller.

## Arithmetic, limits, ownership and SQL

The public factory tests cover C0/global-empty/grouped-empty/static0/static1,
one whole-image epoch at C>0, terminal UINT64_MAX, self joins, hidden/equal-output
keys, full nullable physical rows, invalid identities/arity/types/weights,
duplicate source rows, mixed genuine programs and native-binding corruption.
Reversed parent/child order succeeds; final missing-parent and UNIQUE violations
reject. All 19 AVG scales, compressed extreme signed sums/count limits and the
admitted literal-int32 SUM boundary run without multiplicity expansion.

Four physical rows spanning three groups exercise exact/one-under cumulative
source/native/group/indexed grants. A separate 128-epoch genuine indexed image
requires cold indexed work above the original per-operation ceiling, then resumes
under that unchanged original cap and binding. Receiver denial, same immutable
input after failure and every measured covered C++ new failure position exercise
unpublished cleanup. These are the declared replacement-new/work seams, not a
claim to inject every libc, syscall or account-denial position.

Private receiving overlays additionally retain only weak observations of the
actual cold lease and `AccountedIndexWork` control. Both strong owners expire
after the cold scope and before normal-context allocation while the new runtime
is live. The observers reset before that allocation and are excluded from the
maintained source. This directly checks the closure beyond controller-only
teardown after runtime destruction.

Each maintained reconstruction-oracle profile compares **99 original SQL cases /
198 backend requests / 3,436 atomic epochs / 3,634 snapshots**, with **3,634 actual
reconstructions** at sequence zero and after every committed epoch. SQL recomputes
the physical join/filter/group/COUNT/SUM result; exact AVG uses mature-engine
SUM/COUNT and the established Fraction rounding at scales 0..18. Subsequent
physical commands must still produce exact before/final output diffs. Reference
evaluation functions are unchanged; only native request flags and reporting are
extended. Default predecessor oracle commands retain their behavior.

Separate root-private runs pass DuckDB 1.5.4 with Debug and PostgreSQL 16.15 with
private sanitizer instrumentation; the PG cluster stops. Those runs instrument
six candidate translation units plus test/driver while dependency archives remain
Release. The full maintained sanitizer result above is separate.

## Normal-path cost and provenance

The identical public probe runs against real V23 Release, private candidate
Release and newly installed/relocated Release archives. All **20 scenarios** match
exactly: five SQL forms × both backends × capture settings, ordinary construction,
three committed batches and rollback. Covered C++ new requests, account current/
peak/purpose/lifetime totals, selected source/native/group work, values and output
agree. Observed facade/program/storage/Epoch/Metrics layouts also agree. This is
allocation/work/layout evidence, not CPU timing or a portable ABI claim.

One bounded independent Astra Max static review finds no algorithm/ownership
blocker and identifies the two validation gaps addressed above. Root reviews and
executes the receiving work; Luna supplies source-pinned human contracts. Strict
compilation catches ambiguous runtime-detail qualification and misleading report/
return formatting; root repairs both directly. A mixed genuine tree fails the
real lowerer with `invalid_plan` before snapshot hash comparison, so that fixture
expects the existing carrier. No production error translation is added.

fixture failures, with zero in-command input drift. A later offline-only index
