# Draft independent S04 design review

Status: read/hash/source review only; unfrozen pending root review. The eight [design notes](../s04-index-design-proposal/README.md), native sources and C05 evidence were not changed. No compiler, helper, checker, test, benchmark, symbol tool or process polling was run. [REVIEW_INPUTS.sha256](REVIEW_INPUTS.sha256) records the exact files consulted at this checkpoint; it is not a source seal or an acceptance manifest.

The design is consistent with Refactor.md §6.2 and S04 at the architectural level: an original, noncopyable stable-node backend; exact typed equality after hash filtering; separate live links; explicit finite work; and an unchanged S02 comparison backend. I found no demonstrated algorithmic contradiction in the eight notes. They remain a design, with the following concrete interface and test requirements unresolved before implementation. An unused primitive cannot establish the broader storage/runtime capability required by the full 78-card endstate.

## Concrete details to settle

1. **Specify the private arena undo access.** [CONTRACT.md](../s04-index-design-proposal/CONTRACT.md) requires restoring the same pinned allocation, but [arena.hpp](../../../include/crown/storage/arena.hpp) currently grants access to `TupleArena::revive` only to `ReferenceTable`. The new backend cannot obtain that operation through the existing public API. Choose a narrow internal friend/helper alongside the shared storage-owner allocator. Preserve `revive`'s owner/state, live-bit, pin and generation checks and its nonallocating behavior; do not expose public resurrection or an unchecked owner factory. This is an interface gate, not a reason to replace a deleted tuple with a newly allocated copy.

2. **Close the finite-retention scope explicitly.** The proposed limits cover row/key/member shells, directories and journal retention, but do not name a bound on arena slots or externally retained pins. With one live row at a time, retaining a pin before every erase can grow arena-retained records while table nodes are recycled. Current [arena.cpp](../../../src/storage/arena.cpp) cannot reuse such slots until the last pin is released. Either add separately admitted count limits for those populations or explicitly state which caller-held retention lies outside the primitive's caps. Retain live/retained/free/exhausted/pin counts and destructor-after-last-pin costs. A bounded row-node pool alone is not a bounded total-retention or S05 byte claim; the design already correctly disclaims total allocator accounting.

3. **Require full-hash collisions, not only bucket collisions.** The [acceptance plan](../s04-index-design-proposal/ACCEPTANCE.md) says to make distinct keys share directory buckets. The algorithm first checks the cached full hash. Merely forcing the same masked bucket can exercise chain traversal without exercising equality after equal full hashes. Require both profiles: different full hashes in one bucket, and distinct typed values with the identical full cached hash, in primary and secondary lookup/duplicate/erase paths. Keep the forced-hash authority private to coherent testing variants. Expected membership must come from the independent scalar/row model, not a production hash or equality helper.

The already declared decisions on exact budget-token signatures, capacity policy and runtime exposure also remain required. No production default or unlimited compatibility fallback has been reviewed here.

## Required invariants and evidence

| Area | Source-grounded obligation before acceptance |
| --- | --- |
| Owner identity | [reference.cpp](../../../src/storage/reference.cpp) has one private nonwrapping `StorageOwnerId` atomic. Factor that authority rather than creating a second backend counter. Cross-backend same-relation/same-logical-ID handles must remain foreign. Preserve the separate arena authority and the existing possibility of consumed owner IDs after failed construction. |
| Exact values and support | Keep layout/projection token admission, type tags, NUL/high-byte strings, Date and canonical Decimal exact. [model.cpp](../../../src/ir/model.cpp) hashes the full typed framing and allocates when formatting Decimal; the proposed 41-character formatter allowance is supported by [scalar.cpp](../../../src/ir/scalar.cpp). Pre-admit it and cache hashes outside publication/undo. Membership follows explicit live nodes, never an epsilon, payload value or floating-point conversion. Preserve actual `ProjectionSupportCount` tests at `(1 << 53) + 117`, `UINT64_MAX`, zero and overflow in [support_api_test.cpp](../../../tests/unit/support_api_test.cpp). A separate payload-driver test must not be reported as a valid huge-cardinality runtime census. |
| Traversal | Count empty/first/next/end and every visited chain/member independently. Large retained capacity with zero or one live record must not induce a slot scan. Public key traversal excludes journal-retained empty keys. Define the exact forward zero-to-live key order and independently verify restoration of the original order on rollback. Rehash cannot change that order or tuple addresses. |
| Journals and lifetime | Use retained stable nodes/pins, current directory heads and saved live/member neighbors; never retain links into an obsolete bucket array. Exhaust interacting erase/reinsert/rehash/neighbor sequences. Reserve inverse/finalization work before tentative publication, with no allocation, hashing, copying or fresh grant in commit/rollback. Active journals retain the shared table state after facade destruction, as [storage_journal.md](../../../docs/storage_journal.md) specifies; distinguish facade lifetime from final owner-state destruction. Abort marks owner cursors invalid before undo, and committed data freshness remains separate from the advanced invalidation revision. |
| Owning copies | [ReferenceTable::snapshot_copy](../../../src/storage/reference.cpp) preserves sparse live TupleIds/IndexIds and last-ID/revision values while creating fresh owners and addresses. Public replay alone is insufficient. Rebind all reverse links; copy registered live indexes, not retired external pins; reject active journals. Exercise gaps without invalidating required physical index mappings, source/copy independence, and failed-copy preservation of existing cursors/pins. |
| Finite work and atomicity | One transaction grant must cover every participating table/index plus reserved cleanup, rather than reset per primitive call. Charge comparisons before opaque equality, repeated projection copies, directory initialization/relocation, reverse-link replacement and canonical sorting. Check every sum/product and positive exact/one-under boundary. Specify committed actions versus attempts/no-ops/aborts. Persistent allocation failure must cover each reached preparation position and subsequent cleanup, then a successful retry, preserving complete logical state and only the expressly allowed history metadata. |

The real differential harness must keep three distinct states: unchanged S02, the new backend, and an independently represented scalar/map-of-sets model. Existing [storage_model_test.cpp](../../../tests/unit/storage_model_test.cpp) independently extracts projection slots but still uses native `Value` order/equality; copying that model alone would not establish the proposal's stronger independent scalar oracle. Include literal aliases and boundaries, deterministic generated operation tapes, owning-copy gaps, token rejection, forced collisions, lifecycle, and actual failure positions. Compare every affected bucket and handle/lifetime invariant after each operation, not only a final checksum. Source inspection and visited-node counters are needed for live-only traversal; timing alone is insufficient.

## Full integration remains a separate mandatory gate

The notes correctly identify concrete coupling: [SupportRuntime](../../../src/runtime/support.cpp) owns `ReferencePlanStorage`, its [journal header](../../../include/crown/runtime/support.hpp) names `ReferenceTable::Journal`, and [PhysicalRuntime](../../../src/runtime/physical.cpp) owns reference source tables. A backend-neutral table/journal/cursor facade must preserve one actual owner, exclusive pending-state access, atomic physical alias updates and the same remaining work grant. It must not materialize snapshots to imitate a live cursor. Direct build, replay, rebuild, Support/Physical/Delta/Session/window and actual result/delta cursors need optimized-route oracle and fault coverage while all reference-mode coverage stays intact.

The [physical v1 schema](../../../schemas/physical-plan-v1.schema.json) fixes `reference_ordered_v1`, and [physical IO](../../../src/io/physical.cpp) replays and compares the complete artifact. [GuaranteeProfile](../../../include/crown/ir/physical.hpp) and [DeltaRuntimeProfile](../../../include/crown/runtime/delta.hpp) also state the ordered backend. Resolve a compatible versioned representation and truthful runtime/report capabilities before exposing a hash-backed owner; retain legacy v1 bytes. A hash-table change does not replace D05's separate ordered L/P/B structures or prove stronger public delay bounds.

C01 currently accepts concrete reference tables in [statistics.hpp](../../../include/crown/runtime/statistics.hpp) and [OwnerBuilder](../../../src/runtime/owner_statistics_detail.hpp). Its projection loop does `live()` followed by `get(handle)`; a new ID-directory chain must not become uncharged work. Supply a directly borrowed row/key path or charge all actual lookups through the composed grant. Preserve owning exact facts, unknown incomplete NDV/top-K, actual owner/committed sequence, pending exclusion and independent workload intervals. Changed traversal can change bounded incomplete coverage; capacity retained after rollback is not governed by data freshness alone.

[C05's physical-source encoder](../../../src/planner/selection_binding.cpp) enumerates today's physical options, while [selection admission](../../../src/planner/selection.cpp) restricts layout/index policy and rejects unsupported model/byte requests. Any new backend option must enter full source, artifact and cache identity with exact mutation tests, or fail closed before capture/cache use. C02/C05 logical tuple/index-slot proxies do not estimate new directory capacity or allocated bytes. Actual current/as-of ownership and selection proof authority remain unchanged.

Before the full endstate can claim this capability, root needs the integrated backend, independent semantic/fault/traversal evidence, fair actual-operation measurements with losses retained, coherent production/testing builds, all applicable native matrices and source/artifact review. Primitive-only tests can support a staged storage milestone; they cannot close unimplemented facade/runtime/artifact/profile/report/capture/selection work.

A02's [distribution and provenance record](../../../docs/source_baselines.md) remains open. The proposal copies no legacy code or dependencies and makes no license decision. This review neither resolves A02 nor blocks authorized original implementation. It makes no S04/S05/C05 status transition or measured-performance claim. The reviewer authored prior C01/C02/C05 independent evidence work, not these eight S04 notes or a future S04 implementation.
