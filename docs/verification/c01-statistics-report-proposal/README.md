2026-11-07. **C01 remains `not_started`. This is an excluded, compile-only proposal, not native integration or verification.** The new explicitly selected v3 report captures actual owner statistics and mode context. Default v2 writers, schemas and C01-off behavior are preserved; an enabled C01 collector makes legacy full runtime/session capture fail clearly instead of silently omitting instrumentation. [BUILD_RESULTS.md](BUILD_RESULTS.md) records completed compilation, and [ROOT_REPRODUCTION.md](ROOT_REPRODUCTION.md) contains root-only execution/check commands. ## Explicit version and preserved compatibility

The new API is [StatisticsExplanation](overlay/include/crown/observability/statistics_explain.hpp), with independent [JSON/human export functions](overlay/include/crown/io/statistics_explain.hpp). The type selects schema version 3; it is not a mutable version flag appended to a v2 object. Its scope is owner state/workload plus current and begin-bound O07 mode context. It exports admitted plan identity/checked height, not a replacement full query/tree/proof document. Native physical-plan admission remains authoritative; serialized IDs, hashes and JSON cannot create a report or confer structural proof authority.

Default `PlanExplanation::capture` still produces the existing v2 context when actual C01 mode is off. It performs one additional fixed, nonallocating options read. The native v2 JSON/human writers are unchanged, and no field is added to a closed v2 object. When C01 mode is counters, full legacy runtime/session capture throws `explain_statistics_version`, directing the caller to `StatisticsExplanation`. A dropped session also rejects legacy full capture if its last configured C01 mode was counters. `PlanExplanation::create(runtime.plan())` remains an explicitly compile-only structural path, including tree-only export. The separate frozen-combined control will let root compare exact v2 bytes for runtime and session cases; that comparison has not yet run.

The v3 capability object keeps cost selection unimplemented, estimated total state bytes null, global cost optimality false, and structural proof authority unchanged. **`c01_project_gate = open` is a preparation-only repository acceptance claim. Before the final native C01 matrix, integration must reconcile this constant and its schema/checker fixtures with the accepted repository status. A verified build must not inherit a permanently open C01 gate merely because this proposal used it.** No CLI/version dispatcher is implemented here, and no O08 recovery or public workflow work is attempted.

## Actual owner capture and dependency direction

`StatisticsExplanation::capture(runtime)` captures metadata and bounded admitted workload vectors without an explicit state traversal. Supply `StatisticsCaptureOptions::state` to request selected state facts, and `state_limits` to choose their shared finite budget. Both forms obtain a factory-produced `CombinedCapture`; an absent state request becomes an empty selection list and is exported as `not_requested`, never an invented zero population. The private legacy context helper deliberately does not call the unbudgeted committed-gauge scan.

```cpp
observability::StatisticsCaptureOptions options;
options.state = runtime::statistics::OwnerRequest{{
    {runtime::statistics::SourceScope{TableId{0}},
     std::vector<FieldId>{FieldId{1}}}}};
auto historical = observability::StatisticsExplanation::capture(owner, options);
auto current = observability::StatisticsExplanation::capture(owner, options, &historical, 2);
auto exported = io::write_statistics_json(current, {16 * 1024 * 1024, 1000000});
```

Direct Delta reads obey the native exclusive single-writer contract: no mutation, callback, mode switch or advance occurs between the actual metadata and combined reads. Factory admission reconciles owner, committed sequence, physical plan identity, pending state, actual requested/resolved runtime options, current O07 configuration and C01 mode facts before publishing the report. It does not add concurrent-read support.

Session uses one existing creator-thread/reentry guard to produce a new runtime-only `SessionStatisticsContext`. This private-constructor, immutable owning handle carries actual `SessionReportMetadata`, status, observation trace, optional combined capture, workload options and cursor metadata. It includes metadata-only window private work in the pending barrier. Report construction consumes that complete owning context after the guard exits; it performs no further Session reads. Runtime headers/source contain no observability/report dependency and call no out-of-line report symbol. Both variants successfully link a Session consumer using only the 15-unit runtime closure and foundation archives, without any report objects.

No public constructor accepts caller stamps, availability/exactness switches, arbitrary paired snapshots or an unchecked report context. Internal mutable state/collector builders remain under `src/runtime`. The v3 handle retains no runtime pointer, row pin, cursor lease or journal. Copy-like moves leave both immutable handles readable. Capture/export failure leaves the owner and existing reports unchanged. No update, reset, mode change or drop invokes the allocating report/state export.

## Independent observations and freshness

The state section preserves physical source/native occurrence/generalized records/S/P/E/existing-index distinctions, ordered projection fields, actual derivation multiplicities and exact earlier components when a later component exhausts. Pending private work returns no component facts. Non-connex E is `not_applicable`; unavailable/unknown cardinality, NDV, histogram and top-K values are null with an explicit reason. An exact empty population has known zero NDV and empty arrays. Storage revision is labeled invalidation-only, not committed freshness.

The workload section reports actual off/counters mode, finite cell/detail limits, deterministic period/offset, admitted descriptors, physical input/no-op census, complete sample denominators, abort/truncation metadata, positive/zero crossings, current and previous mode segments, and component memory. Support histograms count unequal support-event after-values. Native touched-degree histograms count actual directed child-event degrees. Generalized probes have the separate `generalized_pre_probe_presence` population and observe 0/1 prior candidate presence. These are event populations, not state NDV or current positive-key multiplicity distributions.

Each ratio carries its denominator scope. Exact/census and deterministic sampled observations remain distinct; no population extrapolation or unbiased estimate is claimed. Incomplete/unavailable/disabled ratios contain null numerators and denominators. Clipped raw counters carry `lower_bound`; clipped or globally saturated data cannot produce an exact ratio. Empty or saturated extrema are null with a reason. C01 takes no clocks and exports no arrival rate. O07's off/counters/timed/trace options and begin-bound/current mode configurations are reported independently, so O07 off cannot imply all instrumentation is off. Caller benchmark labels are explicitly unmeasured declarations and retain exact byte encodings.

Passing a previous factory-produced report requests a comparison against this actual captured owner and an explicit committed-event lag. Data freshness and workload configuration/reset/segment comparisons are separate. Each workload comparison is equality of its own unsaturated generation field in the same owner, **not a unified interval identity**. Segment labels can restart on configure/reset; `segment = same` alone says nothing about continuity when configuration or reset changed. Consumers must inspect all three domains, owner identity and saturation flags together. No fused “current/exact” flag is provided.

A successful no-op advances data epoch. Reset/reconfiguration and mode rotation can invalidate workload comparisons without changing data freshness. Rollback may advance storage revision without advancing committed epoch. Equal rebuilt data remains foreign and rebuilt collection starts off. Availability remains independent: a pending report may have a current data stamp while exposing no exact state component.

Stopped sessions retain the owner and can capture exact committed facts. Drop automatically retains only the newly added fixed C01 options, alongside the native existing O07/status metadata; it does not allocate or preserve a new C01 numeric/state snapshot. A fresh released report has no combined capture, no C01 interval stamp and null state/workload values with `runtime_released`. Its owner/mode/O07 fields are explicitly scoped as last retained metadata. Earlier caller-owned reports remain readable after update, reset, mode switch, move, stop, drop or destruction.

## Exact native transport and export bounds

Every key scalar has a closed type tag and encoding. Strings are lowercase hexadecimal bytes, preserving embedded NUL, invalid UTF-8 and multibyte sequences without replacement. Int64 is emitted as an exact decimal integer token; readers must preserve integer precision. Bool is a boolean under the native `bool` tag. Date uses its finite canonical Gregorian spelling; Decimal uses its exact canonical spelling, never floating point. The tests include both int64 extremes, both booleans, Date endpoints, canonicalized Decimal inputs, raw bytes, ordered/repeated fields and the empty projection/key. Native scalars never acquire SQL NULL; null is confined to explicitly unknown report facts.

`StatisticsTextLimits` independently caps encoded bytes and JSON value items. Each object, array, scalar and null counts as one item; field names do not. Admission occurs before appending the corresponding output bytes/value. Human output has a fixed explanatory preface followed by the same complete structured artifact and counts its preface/newline in the byte cap. A failed limit/allocation publishes no partial string. The producer exercises exact, one-under and zero limits for both formats; the root checker independently counts JSON values.

These are output item/length caps, not total allocator or CPU-instruction bounds. String spare capacity, allocator bookkeeping, fixed scalar formatting scratch and cleanup are additional costs. Ratio lookups traverse already admitted numeric descriptors and can make serialization quadratic in admitted cells; no scan of engine tables is performed by the serializer. State scan work/row/key/accounted-byte limits do not bound serialization.

The accepted state accounted-component payload model and workload retained-vector-capacity model remain separately named, with their exclusions. New report/session-context controls, O07 trace copies, numeric snapshot copies, formatting and caller history retention lie outside the state budget. No total allocator, peak-memory, S05 or estimated total engine-state claim is introduced.

## Proposed verification and remaining limits

The C++ producer checks actual owner bindings and literal source-set/map facts, independent P/E histogram sums, changed/no-op inputs, event/state histogram differences, deterministic samples, whole-detail truncation, pending/prepared/unread/aborted states, reset/reconfiguration/mode comparisons, foreign rebuilds, move/lifetime behavior, stopped/released Session behavior, metadata-only window work, genuinely absent E, generalized pre-probe presence and exact scalar transport. The testing variant seeds clipped values in the actual runtime collector through a private testing-only probe. All inherited combined and workload assertions remain unchanged.

The root-only [checker](check_reports.py) uses installed `jsonschema`, independently recomputes literal rows/groups and alias pre-probe presence, reconciles original/current mode context, checks null/lower-bound semantics and exact byte transport, compares two v2 artifacts to the frozen control, counts exported items and rejects schema/semantic mutations. The saturation fixture seeds metadata, cells and configuration/segment labels together; independent clipping-source cases and reset-generation saturation are not covered by that fixture. It is renderer-path coverage, not a replacement for the accepted numeric collector boundary suites.

Four allocation sweeps propose same-owner recovery checks for actual report capture, JSON export, human export and guarded private-session capture. They cover ordinary allocations used by the fixture types, not a universal aligned-allocation fault framework. Root must observe their injected-position totals and run the complete two-variant sanitizer closure. No execution, schema validation, mutation rejection or v2 byte comparison is claimed from author compilation.

Native runtime/report source registration, explicit version/CLI integration, reconciliation of the preparation-only C01 acceptance field, the full old v2 fixture matrix, broader C01 policies/scalars/constraints/windows, measured native-engine overhead and final native matrices remain later work. Root's separate policy proposal is not silently treated as executed coverage for this report package. C02 ranking, structural proof authority, total allocator accounting and O08 release/recovery remain outside this slice.
