## Scope and tested boundaries

The initial typed expression IR covers scalar comparisons, Boolean AND/OR/NOT,
NULL/Boolean tests, validated literal casts, identity casts and typed positional
parameters. Supported int32-to-int64 promotion is explicit; column narrowing,
lossy fixed-decimal casts and unrelated implicit conversions reject. Typed
date/decimal literals are checked exactly. NULL stays at the SQL boundary and
does not become a classical `Value`. Nullable catalog data may be bound,
without implying it is admitted to the non-null core.

Plain SELECT retains bag mode; DISTINCT retains set mode. Arithmetic/functions,
outer joins, namespaces, CTEs, non-EXISTS subqueries, ordering/limits, grouping,
aggregates and DISTINCT ON fail explicitly in this initial subset. They are
not silently ignored. Work/expression/depth caps are operational limits,
tested through the library at zero budget; they do not establish a global
memory or wall-time guarantee.

The catalog model is explicitly flat, with no table-inheritance hierarchy.
Successful bindings state `catalog_inheritance:none` and preserve the requested
per-occurrence `include_descendants` flag. Default and ONLY scans therefore
read the same declared rows, with different recorded requests. The catalog
schema rejects inheritance-edge fields. This resolves a concrete static-review
finding about a previously discarded `inh` field; it is not a claim to import
or execute PostgreSQL server inheritance catalogs.

## Independent finite evidence

`tests/integration/binding.py` checks 21 successful bindings, 18 diagnostics
and four CLI/configuration errors. Its interpreter enumerates physical-row
combinations and evaluates the bound expression DAG using explicit SQL
three-valued logic. It filters only true predicates, preserves bags, applies
DISTINCT and handles EXISTS separately. Exact scalar values use Decimal/date
objects; checks remain active under Python `-O` and compare JSON types
sensitively.

Manual outputs and independent SQLite row/name comparisons cover applicable
cases. SQLite's NATURAL JOIN wildcard column ordering differs from PostgreSQL,
so that case uses an independently specified PostgreSQL-order layout and
expected rows rather than claiming a matching SQLite dialect. The corpus
includes composite USING, NATURAL with/without common columns, qualified
self-join stars, partial join aliases, comma/ON visibility, repeated outputs,
bag versus DISTINCT duplicates, Unicode name errors, typed parameters,
three-valued predicates, date/decimal casts, EXISTS true/false, a 70-column
star, many input occurrences, zero-arity output and explicit ONLY/default
scan flags. SQL input datasets belong to the test interpreter; no SQL runtime
backend is installed by this work.

The C++ binding unit additionally checks owning lifetimes/copies/moves, source
mutation isolation, cast widths, generic/fixed decimal rules, exact diagnostic
locations, missing parameter types, all three resource caps, flat-catalog
enforcement, and separation of outer/inner EXISTS mode. The remaining 15
previous-stage tests remain green.

All eight schemas pass Draft 2020-12 meta-validation. All 39 actual successful
and diagnostic CLI binding outputs pass their schema and documented exit
status (0/1), with local catalog references resolved. Valid parameter-type
documents also pass their schema. Four invalid CLI/configuration cases check
stderr and status separately. The optional schema audit uses installed
jsonschema 4.10.3, not a new CTest dependency.
