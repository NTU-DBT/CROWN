## Changes and bounded evidence

- `crown_sql` owns UTF-8 source, full PostgreSQL AST, byte statement ranges,
  and copied diagnostics. A noncopyable C-result owner frees parse results
  on success, errors, and C++ exceptions. Calls serialize upstream parsing;
  per-call PostgreSQL contexts are freed, and the top context remains cached
  until thread exit as documented upstream. The CLI bounds file reading to
  1 MiB plus one byte before parsing. Embedded NUL and malformed UTF-8 fail
  before the NUL-terminated C API.
- Independent parser snapshots were produced directly through the pinned C
  library, rather than CROWN. Seven success cases cover comments, quoted and
  folded identifiers, aliases, self-joins, composite expressions, Unicode,
  strings containing semicolons, grouping/bag syntax and DDL. Seven failures
  cover empty input, multiple statements, malformed second statement, encoding,
  NUL, source size and AST nesting. Unit tests repeat 500 success/error/resource
  cycles and test four concurrent callers, ownership, copies/moves and EOF/
  Unicode locations. A separate 8 GiB sparse file returns `resource_limit`
  within the bounded reader check.
- `Date` admits Gregorian 0001-01-01 through 9999-12-31. `Decimal` has a
  canonical exact coefficient of at most 38 digits and scale at most 38, with
  no floating-point conversion or rounding. Typed values and rows have stable
  hashes consistent with equality. The unit test checks 2,004 bounded-rational
  decimal spellings against independent scaled-integer order, explicit signed
  fractions/zero/boundaries, dates, hashed/ordered sets, reference projection
  witnesses and certificate replay.
- Format 2 adds tagged date/decimal values. Format 1's type set and serialized
  form remain intact; writers retain the document's declared format and
  reject new types in format 1. Update formats must match their document.
  Primitive catalog certificate bindings retain format 1; extended catalogs
  bind through format 2. Tree and certificate envelopes remain version 1.
- Independent Python checks use `datetime.date` and exact `decimal.Decimal`
  construction/equality/ordering. Normalization uses text operations, avoiding
  default-context rounding. Seed 1701 has 15 initial date rows/13 normalized
  values and 14 events; seed 4207 has 21 decimal rows/17 values and 14 events.
  Raw aliases reach the native parser. A separate date-by-decimal cross join
  has 3 date-witness and 4 decimal-witness rows with 6 events. There are also
  24 rejected documents and a legacy v1 compatibility check.
- Five schemas pass Draft 2020-12 meta-validation. Actual date/decimal CQ
  inputs and canonical output, three certificate binding variants (date,
  decimal and primitive-v2 input with v1 binding), and all 14 syntax outputs
  pass their schemas. Certificates also pass the standalone replay CLI.
  JSON Schema's integer-token/calendar/precision limitations remain explicit;
  native validation enforces the additional rules.
