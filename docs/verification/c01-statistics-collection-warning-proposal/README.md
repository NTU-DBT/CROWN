# C01 transactional collection warning-only revision

Excluded standalone proposal, 2026-11-07. **C01 remains not complete.** This self-contained revision copies the frozen excluded proposal, whose `package.sha256` is pinned as an input, and changes one runtime expression only. No frozen native source, target, owner, public facade, report or schema is changed. This package complements, and has no dependency on, the separate state-capture proposal. It uses the internal namespace `crown::runtime::statistics_collection`.

## Warning-only change

The only source change from `docs/verification/c01-statistics-collection-proposal/overlay/src/runtime/statistics_collection.cpp` is `inc(bins[std::bit_width(v)],saturated);` to `inc(bins[static_cast<std::size_t>(std::bit_width(v))],saturated);`. For `U64`, `std::bit_width(v)` is in `[0,64]`, so the explicit `std::size_t` conversion is safe and indexes the 65-element array exactly as before; it removes the signed-index `-Wsign-conversion` diagnostic. The public/internal API and all test assertions and expectations are unchanged.

The failed root strict build is recorded in `build/verification/c01-statistics-collection-root-attempt-1.json`. It stopped before any binary execution at `Cell::observe`, `statistics_collection.cpp:22`, because the `int` result of `std::bit_width(v)` was implicitly converted to `std::array<U64,65>::size_type` under `-Werror=sign-conversion`.

## Contract

Explicit `configure` admits a finite descriptor list. Descriptor positions are constant-time hook IDs; identities contain initiating physical table, insert/erase and node/edge/role scope. Physical scope must be zero, identities unique, kinds/operations valid, and each detail descriptor must have its initiating physical table/op descriptor. The caller must select and label omitted strata as not collected and must derive these IDs from an actual admitted plan; this internal component cannot validate native plan ownership. Complete required physical table/op descriptors must be supplied by future owner wiring.

Configure validates cell/count/byte arithmetic, builds a descriptor vector and three numeric slabs (committed, current attempt, one previous segment), then swaps only after all allocations succeed. It has a strong exception guarantee. Configure while pending rejects at this explicit barrier. Off requires an empty descriptor span and retains zero vector payload bytes. A fixed object/status remains.

An admitted `begin` records one physical input with changed/no-op fact, returning the outer ticket. Nested wrappers call `nest(parent)` and finish in reverse order. Each nested ticket has a distinct monotonic serial; stale sibling and prior-attempt tickets cannot publish. Nested success never publishes. Any nested abort poisons the root; only the outer final success merges. An out-of-order finish marks protocol error, poisons the attempt and leaves it open for correctly ordered closure. Invalid physical descriptors fail collector publication with status, without throwing an engine error. Invalid detail IDs/kinds/initiating scopes discard detail while preserving exact known physical counts. This is a single-writer internal interface, not a thread-safe or hostile-ticket API.

Physical committed operation/change/no-op cells are independent of detail sampling and budgets. Metadata separately exposes attempts, commits, aborts, selected, completed, aborted-selected and truncated (including committed-truncated) attempts. Those diagnostic totals may change while private work is pending; committed numeric slabs do not. Invalid/protocol/ordinal-exhaustion flags make degraded coverage explicit. Arithmetic saturation records a lower-bound flag instead of causing an engine failure.

Sample selection uses zero-based admitted attempt ordinal `(ordinal % period) == offset`, including aborted and no-op attempts. Retries consume new ordinals. Period one is census only if coverage has no truncation/degradation/saturation. This is deterministic systematic sampling with no randomness, unbiasedness or confidence claim. Ordinal exhaustion disables further admission with an explicit status until reset/rotation. Ticket serial exhaustion also disables admission and is never reset, avoiding stale-ticket reuse.

Each selected attempt admits at most `detail_budget` actions; one additional action discards the entire detailed sample. All already staged detail is excluded at final publication. Exact physical counters still publish. Every degree hook contributes one observation, including repeated values and zero; there is no key copy or deduplication. Occurrence counters distinguish visited/accepted/rejected. Support hooks distinguish every unequal before/after change from the two directional zero crossings; its histogram observes **after-values of changed support events, including zero**, not positive stored-key population. Equal before/after values use one action but produce no change observation.

The 65 integer bins are zero and `[2^(b-1), 2^b-1]` for b=1..64 (last upper bound UINT64_MAX). Count/sum/min/max are exact when unsaturated. Empty min/max are unknown despite zero-initialized storage. A cell saturation flag invalidates derived exact means; no quantile interpolation or inverse-probability expansion is implemented.

Hot begin/hooks/finish/abort/reset/rotate are noexcept and allocate nothing. Work is O(H guards + min(H,B) actions + K clears/merges), with actual guard visits, admitted detail actions and cleared/merged cell visits reported. A cell merge touches a fixed 65 bins; cell visits are not claimed to equal machine instructions. Reset clears all three slabs, both metadata intervals and sample ordinal, increments saturating generation, and leaves ticket serial identity intact. Pending reset/rotate returns false. Rotation is called only **after** an actual successful semantic mode change; equal configuration IDs are a no-op. It swaps committed into the single previous slot, clears new current scratch and starts a new sample interval, recording previous/current configuration and replaced history. This component cannot itself validate semantic switch success.

`memory()` reports actual vector capacities times element sizes, separately for descriptors and three slabs, plus `sizeof(Collector)`. Retained payload excludes the object; object plus payload is checked for size_t overflow at configure. Allocator metadata/rounding, old+new configuration overlap, engine storage, caller snapshots, diagnostic reports and other components are excluded. This is component requested payload accounting, not S05 total allocator/live-byte evidence.

There are no clocks and no timing integration. Counters/off never read clocks. There are no external callbacks, owner stamps, native data epochs, immutable owning reports or bootstrap/session hooks. Borrowed committed/previous spans expire on reconfiguration or mutation and are not report snapshots.

## Validation status and root commands

Both commands below compile and link the normal and ASan+UBSan test binaries with the full project warning set on 2026-11-07. They deliberately do not execute the binaries or run any checker, CMake or CTest. Root must run and record results independently. Assertions require builds without `NDEBUG`.

```sh
c++ -std=c++23 -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Werror -UNDEBUG -O0 -g -I docs/verification/c01-statistics-collection-warning-proposal/overlay/src/runtime docs/verification/c01-statistics-collection-warning-proposal/overlay/src/runtime/statistics_collection.cpp docs/verification/c01-statistics-collection-warning-proposal/overlay/tests/unit/statistics_collection_test.cpp -o /tmp/crown-c01-collection-warning-test
c++ -std=c++23 -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Werror -UNDEBUG -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -I docs/verification/c01-statistics-collection-warning-proposal/overlay/src/runtime docs/verification/c01-statistics-collection-warning-proposal/overlay/src/runtime/statistics_collection.cpp docs/verification/c01-statistics-collection-warning-proposal/overlay/tests/unit/statistics_collection_test.cpp -o /tmp/crown-c01-collection-warning-sanitized-test
```

The standalone tests independently assert transaction nesting/abort/invalid-ticket behavior, sampling denominators, physical no-ops, selected truncation after nonzero staging, exactly-at and zero detail budget, repeated degree events, support crossings, all power-of-two bin boundaries, saturation, generation/ordinal boundaries, reset, rotation/history replacement, vector-capacity memory identities, four allocation-failure points in strong configure, and hot paths under a globally rejecting allocator. A narrowly named friend permits numeric-boundary injection only in the test translation unit. No billion-event execution is implied.

Owner/session hooks, plan-derived descriptor admission, initialization suppression, actual successful-mode handoff, data stamps/freshness, state-capture composition, public immutable report wiring, EXPLAIN/schema, optional active-time scopes, benchmark measurements, full native/sanitizer matrices and C01 acceptance remain unfinished. Standalone fixtures cannot prove native rollback integration or all-off engine parity.
