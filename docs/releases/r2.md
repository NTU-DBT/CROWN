# R2 candidate packaging and qualification

R2 adds the admitted exact SQL bag and aggregate contracts in
[Refactor §0.1, W01–W06 and V04](../../Refactor.md) to the separately qualified
[R1 equality-set engine](r1.md). The release profile, project version 0.1.0 and
public API version 1 are separate identifiers. An R2 package is a
`candidate_unqualified` image with `release_accepted: false` until its exact
source, SDK, report and validation evidence receive a separate scoped decision.
This method does not declare that decision.

## Advertised interfaces and limits

Use [the compatibility matrix](../r2_compatibility.md) and
[migration notes](../r2_migration.md) to choose a genuine query family:

| Query family | Public workflow and output |
| --- | --- |
| R1 equality sets | The existing CLI/library path, duplicate-free rows and signed membership changes. Its admitted SQL and strict minimum-height policy retain their R1 rules. |
| Nullable SQL rows | `CROWN::sql_rows` for in-memory plain bags, DISTINCT and EXISTS; `CROWN::sql_rows_recovery` for the durable C++ workflow. Bag changes carry an exact sign and uint64 magnitude. DISTINCT uses unit support; EXISTS retracts/inserts the old/new Boolean row when presence changes. |
| Original SQL aggregates | `CROWN::sql_aggregate_runtime` and `CROWN::sql_aggregate_recovery`, plus the documented `crown aggregate` input workflow. Admitted COUNT/SUM/AVG retain full group identity, NULL/global-empty behavior and complete before/after group changes. |

A lower logical-bag `CROWN::aggregate` consumer does not establish original SQL
source admission or durable SQL aggregate behavior. The plain-row durable API
has no new CLI command. The CLI's existing `--version` text describes its exact
set workflow; selecting an R2 package profile does not change that text or the
native execution policy. Match headers and libraries from one SDK and recompile
consumers; no cross-SDK binary-layout compatibility is promised.

Read [the row Session](../sql_rows_session.md),
[the aggregate Session](../sql_aggregate_session.md),
[SQL row admission](../sql_rows_runtime.md) and
[aggregate admission](../sql_aggregate_binding.md). Physical identity includes
hidden, filtered and unused source rows. Arithmetic domains, overflow refusal,
NULL typing, final-state batch constraints and output representation remain
explicit per interface. The two durable owners have one logged head and one
committed output spool, physical-source checkpoints and exact local replay.
Their default retained-history cap is 128 absolute selected generations with
floor one and no R2 retirement operation. Reopening does not refill that usage.

Descriptor source/native/output policies and receiving operational limits have
different roles. Receiving account, codec/file/replay and rebuild limits keep
their own documented scopes. Resource refusal does not become a semantic Reject;
uncertain file mutation requires reopening. Linux regular-file, cooperating
advisory-lock and namespace/fsync premises apply. Process-cut tests do not prove
hardware power-loss behavior. Local byte-confirmed duplicate delivery supplies
no arbitrary external exactly-once service guarantee.

Numeric/source/output/durable work does not inherit the Boolean maintenance
bound. SQL output decode, intermediate capture, packed-key sorting/copy/hash,
checkpoint/rebuild and last-owner cleanup are real costs. Ordinary row binding
keeps recovery-image retention off and preserves its original large-parameter
memory bound; durable binding requests the additional cold accounted image.
There is no new runtime layer in package-profile selection.

## Assemble an explicit R2 candidate

Use a fresh output prefix and the supported toolchain in
[native build](../native_build.md). A matching source/build identity is a
receiving requirement; copying files from an arbitrary build is insufficient.

```sh
cmake -S "$task_source" -B "$task_build" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$task_cxx" -DBUILD_TESTING=OFF
cmake --build "$task_build" --parallel 2
PYTHONDONTWRITEBYTECODE=1 python3 "$task_source/tools/package_release.py" \
  --profile R2 --source "$task_source" --build-dir "$task_build" \
  --report "$task_r2_report" --figures "$task_r2_figures" \
  --evidence "$task_closed_evidence" --output "$task_new_output"
```

Omitting `--profile` preserves R1; explicit `--profile R1` has the same R1 scope.
R2 uses `crown-next-0.1.0-r2.tar.gz`, a matching root name and `profile: R2` in
its manifest. Both profiles remain unqualified. Accepted R1 files are never
renamed or rewritten to produce R2.

The archive retains the [R1 regular-file layout](r1.md#build-and-assemble):
`sdk/`, complete maintained `source/`, `report/`, `figures/`, closed `evidence/`,
manifest and sorted checksums. The R2 README starts at `report/r2-report.md` and
this method, with the compatibility/migration and actual Session guides.
Normalized member metadata and deterministic gzip/tar rules are unchanged.
Packaging grants cover staged regular payload files/bytes; installer staging,
metadata, compression, temporary storage and process resources remain separate.
Packaging changes no query semantics, default height, runtime hook or query
memory-account rule.

The extended report uses an outer R2 entry/hash index around the unchanged
historical six-study report and figures. V48 B05, V59 planning, V60 operational/
matched/search and V61 specialization retain their original source/units and
measurement qualification. The role named current source inside that frozen
report remains V61. Current semantic/resource/recovery/SDK receipts are a
separate addendum. Correctness-test elapsed values are not benchmark samples;
no controlled latency, throughput or speedup is claimed for the new durable
plain-row path. Its logical costs and resource limits remain visible.

## Receive the actual image

Validate normalized regular members, the outer archive hash, release manifest
and every checksum. Copy/extract into a fresh prefix, move the SDK, and compile
outside consumers with only its public headers, exported targets and SDK
archives. Inspect compiler dependencies and actual linked libraries; source-tree
or producer-build resolution is not an installed-image trial.

Exercise admitted unseen SQL and exact update/output behavior against independent
oracles. For advertised durable paths, include complete physical state,
W/I/C/D progress, pending/undelivered recovery, checkpoint/next-update behavior,
resource/semantic separation and actual sink-byte coverage. A generic COUNT/SUM
primitive fixture has its own narrower scope. Bind SQL aggregate/AVG/NULL and
durable claims to their genuine current tests and actual source/native/SDK
lineage; old SDK bytes alone cannot qualify another image.

A clean source build is separate from SDK relocation. Join compiler commands,
project/generated/system dependencies and target bytes to the packaged source.
Release-tool-only changes can receive their targeted regressions while exact
unchanged native inputs/bytes retain their prior qualified native tests. State
those source vintages explicitly; never rename an older suite as a new full
source-point execution. The [V63 component review](../verification/sql-rows-recovery-v63-2026-11-16.md)
records both actual 383-test profiles and their 858-input source point.

## R2 checklist and decision

| Requirement | Evidence to receive for the exact candidate |
| --- | --- |
| V03 prerequisite/R1 preservation | Accepted R1 archive/decision retained, current set/proof/default-height results and matching source/compiled inputs. |
| W01–W03 exact annotations/bags | Independent arithmetic/message/projected-multiplicity checks, zero/nonzero and positive-to-positive changes, wide signed output and representation/resource scopes. |
| W04–W05 SQL semantics | Genuine admitted COUNT/SUM/AVG and row behavior, NULL joins/grouping, empty global/grouped results, signed sums/count domains, deletion of the last row and declared AVG rounding. |
| W06 transactional recovery | Atomic physical replacement, cancellation/consolidation, arithmetic rollback, physical checkpoints, replay and interruption/next-update checks. |
| V04 documentation/report | Exact compatibility/migration bytes, portable R2 addendum with original measured vintages, current exactness/resource/SDK receipts and no invented performance claim. |
| G10 independent correctness | Current independent exact/SQL oracles for the advertised bag/aggregate contracts; finite cases supplement their source arguments. |
| G11 actual package | Complete source/SDK/report/evidence identity, current or explicitly inherited unchanged-input regressions, fresh build/relocation and unseen-query workflow with matching docs/limits. |
| Separate decision | A root-issued scoped technical decision identifies the exact archive and remaining limits; assembly/hash success alone does not accept V04. |

Keep every R3 backend behind its own gate. Comparisons, top-k and difference may
use ordinary change propagation or exact recomputation. Approximation,
shared-query optimization and parallel/distributed execution remain deferred;
each query retains an independent serial owner. Preserve existing rights and
dependency notices. The user-deferred licensing disposition is not reopened by
this technical checklist.
