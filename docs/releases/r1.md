# R1 candidate packaging and qualification

R1 is the free-connex equality set engine defined in [Refactor §0.1 and V03](../../Refactor.md).
The release milestone and native API version are different identifiers: this
candidate uses project version 0.1.0 and public API version 1. Packaging remains
unqualified until the gate checklist, exact source/build identity and actual
validation evidence receive a separate release decision.

The supported path is SQL/catalog admission, independently checked minimum-height
planning, immutable physical compilation and serial native maintenance. The
documented fragment includes arbitrary finite relation arity and tree fan-out,
projection, Boolean/disconnected queries, self-joins, insertion/deletion, current
results and signed deltas. Finite compilation grants can stop exact search;
an upper witness never becomes a minimum certificate after a timeout.
Read [SQL support](../sql_support.md), [guarantees](../guarantees.md),
[planner proofs](../planner_proofs.md) and [output costs](../ordered_delta.md).

R1 uses the general executor and explicit C02 ranking policies. Optional C03
estimates remain conditional/offline; C05 maintenance_cost is unsupported.
Prepared SQL input dispatch is opt-in, with the interpreter as default.
Independent-query ownership is serial and provides no shared-state savings.
Installed bag/aggregate libraries retain their separate R2 contracts; their
presence in an SDK does not silently enlarge this R1 qualification. Comparisons,
top-k, difference and general-query fallback retain separate extension gates.
Approximation and parallel/distributed execution remain deferred.

## Build and assemble

Use a fresh output prefix. A supported native toolchain and dependency notices
are described in [native build](../native_build.md); the current verified build
uses Linux, GCC 13 and C++23. CMake and GNU Make build the vendored checksum-pinned
parser archive without network access. Python is needed for packaging and tests.
The package does not supply the host's compiler, libc or C++ runtime.

```sh
cmake -S "$task_source" -B "$task_build" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$task_cxx" -DBUILD_TESTING=OFF
cmake --build "$task_build" --parallel 2
PYTHONDONTWRITEBYTECODE=1 python3 "$task_source/tools/package_release.py" \
  --source "$task_source" --build-dir "$task_build" \
  --report "$task_report" --figures "$task_figures" \
  --evidence "$task_closed_evidence" --output "$task_new_output"
```

Report, figures and evidence must be existing nonempty regular-file directories.
The tool copies exactly those inputs and records their hashes; it does not
interpret them as passing tests or verified measurements. Use the complete
qualified report and closed gate evidence for the actual release candidate.
Small subsets are useful only for testing packaging. Root output, install logs,
partial failures and the unpacked stage remain inspectable. An existing output
directory is rejected before installation; failed new attempts are retained.

The archive `crown-next-0.1.0-r1.tar.gz` contains one root with:

| Path | Usage |
| --- | --- |
| `sdk/` | Relocatable installed CLI, public headers/libraries, CMake package, schemas, examples and dependency notices. Testing/reference archives are excluded. |
| `source/` | Exact maintained source, complete source documentation/usage specs, vendored dependencies and the baseline manifest's pinned source inputs. Build, VCS and account directories are excluded. |
| `report/` and `figures/` | Explicit portable raw/table/methodology and figure inputs. Historical timing/source vintages keep their own qualification. |
| `evidence/` | Explicit closed release-check inputs, with their original scopes. |
| `release-manifest.json` | Version/API/build configuration, regular payload hashes/sizes, packaging grants and unqualified status. |
| `CHECKSUMS.sha256` | Sorted standard hashes of every payload plus the release manifest; excludes itself. |
| `README.md` | Entry points and relocation/build instructions. |

The tar uses regular files, normalized ownership/times and executable modes;
gzip uses an empty filename and time zero. Identical inputs with the same
Python/zlib implementation have deterministic archive bytes. No cross-version
compressor identity is promised. Historical build-evidence links in unchanged
source documents retain their original repository context. Portable release
qualification is in `evidence/` and the report, not an old-path fallback.

`--max-files` defaults to 50,000 and `--max-total-bytes` to 2 GiB. These bound
regular staged payloads, including the installed SDK and README. Installer
staging occurs before those files are charged; metadata, compressed output,
temporary disk space and Python/process resources have separate costs. Packaging
scans/copies/hashes the inputs and compresses the full image; it adds no query
runtime hook, memory charge or execution branch.

## Receive an extracted candidate

Check the outer archive hash, normalized members, manifest and all checksums.
Extract to a fresh directory, move the SDK, then compile an outside consumer
using only its `CrownConfig.cmake`, headers and exported targets. The consumer
must not resolve original source/build includes or testing/reference libraries.
Compile unseen supported SQL through normal admission, compare exact snapshots
and deltas with an independent oracle, checkpoint, restore in a new owner/process
and apply the next update. The [quickstart](../quickstart.md),
[CLI workflow](../cli.md) and installed native-workflow example show that API.

A fresh source build from `source/` is a separate gate from SDK relocation.
Keep its compiler commands/dependency closure, source hashes, target bytes and
raw test results. A packaging command cannot prove that an arbitrary input
build was compiled from the advertised current source. Do not mix archives from
another revision or relabel historical passing suites as current.

## Release checklist

| Gate | Required acceptance |
| --- | --- |
| G0 | Exact model, update/output semantics and pinned sources; preserve rights/notices. Licensing disposition is deferred by the user. |
| G1 | SQL binding/normalization equivalence and precise rejected syntax. |
| G2 | Structural validity, independent minimum evidence, exhaustive finite controls and honest resource stops. |
| G3 | Committed support/count state matches independent subtree semantics. |
| G4–G5 | Exact snapshots and projected additions/deletions, with all eager preparation and cleanup costs included. |
| G6 | Atomic logical updates, cursor lifetime, cancellation, batching/window and per-query isolation. |
| G7 | Checkpoint/WAL/replay/local-sink crash boundaries, exact state/next-update behavior and resource denial. |
| G8 | Source-bound raw counters, output and memory scopes, adversarial scaling and retained adverse observations. |
| G9 | Deterministic admitted C02 selection; optional optimizer claims retain their separate evidence. |
| G11 | Versioned package, current full regression evidence, fresh source build, relocated unseen-query workflow and matching human documentation. |

G10 and V04 add bag/aggregate qualification for R2. Each extension has its own
gate. An unfinished optional extension does not invalidate a completed core;
it stays outside the advertised core scope. The final release receiving records
the exact current matrix, mandatory regression-case coverage and remaining
limitations. A candidate remains internal until that advertised scope passes.
